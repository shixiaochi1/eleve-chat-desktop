## 二、🔴 死/断线（共 8 项）

### D1：slash_confirm GUI 对话框（🔴 高）

**现象**：破坏性斜杠命令（/new, /undo, /reset）在桌面端无 GUI 确认对话框。

**根因**：
- 后端 `slash_confirm.rs` 注释："GUI 模式 — 桌面端原生对话框（**未来实现** send_slash_confirm 回调）"
- 当前走**文本回退**：api_server.rs:2284 返回 `"⚠️ /{} will {} your conversation. Reply /approve to confirm..."`
- 后端**不推 `slash_confirm.request` SSE 事件**
- 前端 useSSE.ts:104 有类型定义但**无 case handler**

**修复方向**：后端增加 WS 事件推送 + 前端新增 SlashConfirmCard 组件（参考 ApprovalCard）

---

### D2：session.archive / unarchive 后端 stub（🔴 高）

**现象**：右键"归档"点击后 UI 显示已归档，但后端无持久化，重启后复活。

**根因**：
- 后端 mod.rs:2091 返回 `"not yet implemented in session_db"`
- 前端 SessionsPanel:275 调用后静默成功
- 前端用 localStorage `ARCHIVED_KEY` 做 UI hiding（:232），纯前端假象

**修复方向**：后端 session_db 增加 archived 字段 + 真实实现；前端删 localStorage 假持久化

---

### D3：Voice 录音/TTS 后端 stub（🔴 高）

**现象**：VoiceSettings 配置可读写，但录音和 TTS 完全不工作。

**根因**：
- 后端 voice.record（mod.rs:3332）是 TODO stub（返回固定 JSON）
- 前端 useVoice hook UI 状态机已搭好（idle→recording→transcribing→idle），监听 voice.transcript 事件
- **前端就绪，后端未实现**

**修复方向**：
- 短期：前端 VoiceSettings 加"开发中"标识，禁用录音按钮
- 长期：后端实现 VAD + STT + TTS（对齐 Hermes voice.*）

---

### D4：ChannelsPanel 假数据（🟡 中）

**现象**：频道面板显示硬编码 WeChat 频道，非真实数据。

**根因**：无专用 channels API。useChannels 从 gateway_status.platforms 推断，失败回退 `fallbackWeChatChannel()` 硬编码。

**修复方向**：后端增加 channels.list RPC；前端删 fallback 假数据

---

### D5：ToolCallCard 孤儿组件（⚪ 低）

**现象**：`src/components/ToolCallCard.tsx`（105L）零消费方。

**根因**：MessageContainer 使用 ToolCallGroup（内部渲染独立卡片），ToolCallCard 被完全绕过。

**修复**：确认后删除。

---

### D6：useActivityTimer 死 hook（⚪ 低）

**现象**：`src/hooks/useActivityTimer.ts` 零消费方。

**修复**：直接删除。

## 三、🟡 半活（能用但有缺陷，共 2 项）

### S1：UsagePanel 数据质量

- analytics_usage RPC 后端有，前端 useUsage 调用正常
- useUsage 有 localStorage 本地兜底（后端不可用时），可能误导
- 数据准确性取决于后端 tracking 完整度

### S2：StatusBar 信息密度极低

- 只显示连接状态（online/offline/checking）
- 无 session 信息、无 token 用量、无当前模型名、无 profile 名
- 对比 Hermes 桌面端状态栏差距大
