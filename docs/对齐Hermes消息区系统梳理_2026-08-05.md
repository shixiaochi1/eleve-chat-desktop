  └─ 历史消息：切会话时从缓存恢复（后端会话库为权威源）

## 2. ELEVE 消息区架构明细

### 2.1 数据模型（`lib/chat-messages.ts`，单一权威源）

```ts
ChatMessage { id, role: 'user'|'assistant'|'system'|'tool', parts: ChatMessagePart[],
              timestamp?, pending?, error?, hidden?,
              + 一打 legacy flat 字段（type/content/reasoning_content/tool_*，兜底用） }

ChatMessagePart = TextMessagePart | ReasoningMessagePart | ToolCallMessagePart
  ├─ TextMessagePart       { type:'text', text }
  ├─ ReasoningMessagePart  { type:'reasoning', text, done? }   // done=已 reasoning.end 冻结
  └─ ToolCallMessagePart   { type:'tool-call', toolCallId, toolName, args, argsText, result?, isError?, status? }
```

- parts 按**到达序**交错（reasoning → text → tool 混排），流式骨架与落定结构同构 → 完成无 DOM 突变
- 操作纯函数：`appendTextPart / appendReasoningPart / freezeReasoningPart / upsertToolPart`（lib/chat-messages.ts:138-420）

### 2.2 流式累加（`lib/ws-event-processor.ts`）

- `StreamAccumulator`：parts 数组 + serverContent + step 边界标记
- `processAccumulatorEvent`：reasoning.available 种占位、reasoning.delta 并入未冻结块、reasoning.end 冻结（多推理块支持）
- `finalizeAccumulator`：空 reasoning 占位过滤 + **重复流去重**（拼接 > 后端终稿 2 倍 → 用权威 content 替换）

### 2.3 状态与缓存（`store/messages.ts` + `lib/session.ts`）

- 纯内存 zustand-like store（useSyncExternalStore 实现），无中间持久化层
- 会话切换时 `saveCache()` 把消息快照写 localStorage（per-sessionId 键控）
- 后端会话库是历史消息权威源（前端启动/切会话时经 WS 拉取）

### 2.4 渲染树（`MessageContainer` / `MessageRow`）

- `VirtualizedThread`：@tanstack/react-virtual + 分组渲染（buildGroups 按消息签名：user/assistant 轮次分 turn 组）
- `MessageRow`（纯函数组件，单视图/宫格共用）：
  - reasoning → `ReasoningBlock`（8/5 起 markdown 渲染：StreamBlocks 管线 + trimStart + useDeferredValue）
  - text → `MessageBubble`（w-fit 自适应 + useSmoothReveal 段落边界回退 + useDeferredValue + enter 动画）
  - tool → `ToolEntry`（独立成行，callId 稳定 key，状态机 pending/running/done/error）
  - 附加：HoistedTodoPanel（todo 提取）、StreamStallIndicator（12s 停滞提示）
- 单视图（VirtualizedThread）与宫格（AgentChatCard）共用 MessageRow，零重复

### 2.5 Markdown 管线（`utils/markdown.ts` + `StreamBlocks.tsx`）

```
mergeSingleNewlines（单换行折叠，块语法感知）
  → autolinkOutsideFences（裸 URL，fence 感知）
  → repairMarkdownTail（尾部未闭合构造修复：fence/行内 code/强调/链接）
  → splitMarkdownBlocksCached（fence 感知空行切块 + LRU 缓存）
  → 逐块 renderMarkdown（marked + DOMPurify + hljs，流式尾块延迟高亮）
```

- 大文本降级：流式 >40k / 完成 >100k → 纯文本分块 + content-visibility
- 代码卡片：`.code-block-wrapper`（语言标签 + 复制按钮）

## 3. Hermes 消息区架构明细（含运行数据实证）

### 3.1 存储模型（`AppData\Local\hermes\state.db` 实证）

**messages 表**（扁平行，24 列）：

| 列 | 用途 |
|---|---|
| session_id / role / content | 基础 |
| tool_call_id / tool_calls / tool_name | 工具调用（tool_calls=JSON） |
| **reasoning / reasoning_content** | **双写**（实证 4006 条两列同值；reasoning=原生，reasoning_content=API 回放对齐） |
| reasoning_details / codex_reasoning_items / codex_message_items | 更多推理形态（codex 专用） |
| **display_kind / display_metadata** | UI 特殊显示形态（实证分布：async_delegation_complete 9 / auto_continue 3 / hidden 1 / model_switch 8） |
| active / compacted / observed | 软删（active=0 保留审计）/ 压缩标记 / 已观察 |
| finish_reason / token_count / effect_disposition / api_content | 元数据 |

**sessions 表**（44 列）：usage 四件套 + cost 六件套 + handoff 三件套 + compression 状态 + profile_name / pinned / git 上下文 / title。

**其他**：messages_fts（FTS5 + trigram 全文检索）、desktop/sessions.json（桌面会话清单，source=desktop，messageCount 实时）。

### 3.2 前端消费形态（`lib/chat-messages.ts:341-389`）

- `display_kind='hidden'` → 不进 transcript
- `model_switch` / `auto_continue` / `async_delegation_complete` → 特殊 UI 形态（前端有专门处理分支）
- 前端还有 user-edit-composer（用户消息编辑）、message-reactions、timeline（会话引用/分界）、compaction 恢复提示、system-message 形态

### 3.3 渲染（thread/ 组件树）

- `ThreadMessageList`：structural signature memo（流式 part 追加不破坏行 memo）+ buildGroups + **liveTailStart**（流式尾巴渲染预算）+ render budget（首屏分片）
- `MessagePrimitive.Parts` 组件表：Reasoning / ReasoningGroup / Text / ToolGroup（Fallback/Delegate/ImageGenerate/Clarify 专用工具渲染）
- streamdown（@assistant-ui/react-streamdown）：块级流式 markdown + tailBoundedRemend + preprocessMarkdown + 代码插件（Shiki，defer 延迟高亮）+ KaTeX（memoized）+ ArtifactCard（大代码块提升右栏）+ mermaid/svg fence 路由
- ReasoningGroup：多 reasoning 块聚合 + `open = userOpen ?? pending` 三态 + 高度门控 RO 滚底 + 块级 timerKey

## 4. 差异对照表

| 维度 | Hermes | ELEVE | 差距 |
|---|---|---|---|
| 消息权威源 | state.db（gateway 落库，soft-delete 审计） | 后端会话库 + 前端内存 store | ✅ 语义等价（ELEVE 后端负责落库） |
| 前端消息模型 | DB 扁平行 → 前端按 type 重组 parts | parts 数组（到达序交错） | ⚠️ 形态不同，语义一致（8/4 已对齐到达序） |
| reasoning 存储 | 多形态（reasoning/content/details/codex_*） | 后端剥离后单字段 reasoning | ⚠️ ELEVE 后端单形态，够用但无 codex |
| reasoning 渲染 | markdown 渲染（streamdown+code card） | **8/5 已对齐**（StreamBlocks 管线） | ✅ 刚修完 |
| 主文本渲染 | streamdown + Shiki + KaTeX + ArtifactCard + mermaid/svg | marked + hljs + 代码卡片 | 🚧 KaTeX/mermaid/Artifact 已列任务补齐（TASK-katex-math-render / TASK-mermaid-render / TASK-artifact-card，2026-08-05） |
| display_kind 特殊形态 | hidden/model_switch/auto_continue/async_delegation_complete | 无（后端无此字段） | 🔴 缺口（若后端对齐 Hermes display_kind 则前端要补） |
| 压缩（compaction） | compacted 标记 + 恢复提示 | 无前端表现（后端压缩透明） | ⚠️ 待确认后端压缩事件是否推前端 |
| 全文检索 | messages_fts（FTS5+trigram） | 无 | 🔴 缺口（若要做消息搜索需后端加） |
| 用户消息 | UserMessageText + **user-edit-composer（编辑）** | UserMessageText（最小 markdown） | ⚠️ 编辑功能缺口 |
| 反应/时间线 | message-reactions + timeline（会话引用） | 无 | ⚠️ 依赖后端能力 |
| 虚拟化 | 自研 budget + liveTailStart | @tanstack/react-virtual | ✅ 等价 |
| 流式优化 | structural signature memo + defer | 块 memo + useDeferredValue + reveal | ✅ 等价 |
| 工具渲染 | ToolGroup 分组 + 专用工具组件（Delegate/Clarify/ImageGenerate） | ToolEntry 独立成行（8/4 对齐不分组） | ✅ 语义对齐 |
| 消息持久化 | DB 权威 + FTS + 压缩 | localStorage 缓存（per-session）+ 后端库 | ✅ 架构等价 |

## 6. 结论

ELEVE 消息区**渲染层已高度对齐 Hermes**（8/1 气泡审查 + 8/5 思考块修复后）。**2026-08-05 老大指示三项渲染增强全部补齐**（KaTeX / mermaid / Artifact —— 前两者属消息区渲染管线，后者独立 P0 任务，均已在 `Eleve Agent/tasks/` 列任务）。**结构性缺口集中在数据形态层**：display_kind 特殊消息、compaction 恢复提示、消息编辑、FTS 检索——取决于后端是否对齐 Hermes 对应能力，前端只需在 RPC/事件契约出现后补渲染分支。建议按"后端对齐到哪、前端补到哪"的节奏推进，不提前造 UI。
