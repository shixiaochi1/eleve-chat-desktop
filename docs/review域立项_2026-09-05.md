# Review 域立项（右栏 git 工作区审查）— 2026-09-05

> 对齐 Hermes `apps/desktop/src/app/right-sidebar/review/` + `store/review.ts`。
> 目标：右栏新增 Review 域——工作区未提交变更的审查与处置：文件列表/树、选中
> 文件 diff、stage/unstage/revert、commit/commitPush、AI commit message。
> 打通"agent 改完 → 人工审查 → 处置 → 提交"闭环。

## 0. 范围

**范围内**：uncommitted scope 的完整审查与处置（Hermes 注释自认 "Scope is
always uncommitted"——branch/lastTurn 档实际恒空，不做，RPC 参数位预留）。

**范围外**：PR 域（gh pr view/create + shipInfo，依赖宿主机 gh CLI，环境不可控，
单独立项）；`git.review_pr_list` / `git.review_ship_info` 不实现。

## 3. 架构设计（铁律落点）

- **数据源唯一**：git 是唯一权威源。前端零持久化（树/列表布局、commit 默认动作
  两个 UI 偏好除外）；每次变更操作后 `afterMutation()` 全量重同步（对齐
  review.ts:371-382），不做乐观更新——agent 与用户并发改仓库是常态。
- **并发守卫**：refresh 单调 seq + 返回前 cwd 双校验（对齐 `reviewRefreshSeq`/
  `repoCwd()`，review.ts:129-134）；ship 动作单 busy 串行化防双击（对齐 `runShip`）。
- **刷新边界**（事件驱动，不轮询）：① 面板打开/reveal；② workspace tick →
  100ms debounce（`REVIEW_REFRESH_DEBOUNCE_MS`）；③ turn 落定边沿
  （`sessionListVersion` bump）；④ cwd 变更 → 先清列表+选区再 refresh（对齐
  `onReviewRepoMoved`，防闪现旧仓库 diff）；⑤ 窗口 focus；⑥ 变更操作后。
- **安全红线**：revert 永远过确认对话框（`{path|null}` 区分单个/全部）；gateway
  侧 file 参数校验 resolve 后必须在 repo root 内（防路径逃逸）；非 git 仓库返回
  结构化 `{ is_repo: false }` 而非空列表。

## 4. RPC 规范（全部 `git -C <root>` 执行；cwd 侧为仓库内任一路径）

| RPC | 参数 | 返回 | git 语义 |
|---|---|---|---|
| `git.review_list` | `{ path }` | `{ is_repo, files: [{path, added, removed, status, staged}] }` | `status --porcelain=v2 -z` 解析 staged/unstaged 双区 + `diff --numstat` 合并增删；status 字母 M/A/D/R/C/U/? |
| `git.review_diff` | `{ path, file, staged? }` | `{ diff }` | staged ? `diff --cached -- file` : worktree diff；untracked 走 `--no-index`（复用 files_diff 公共逻辑） |
| `git.review_stage` | `{ path, file? }` | `{ ok }` | `git add -- [file]`（file null = `-A`） |
| `git.review_unstage` | `{ path, file? }` | `{ ok }` | `git reset HEAD -- [file]` |
| `git.review_revert` | `{ path, file? }` | `{ ok }` | tracked → `git checkout -- file`；untracked → 删除文件；staged-added → unstage 后删；file null = 全部（**仅 uncommitted，前端确认框强制**） |
| `git.review_commit` | `{ path, message, push? }` | `{ head }` | `commit -m`（+ `push`）；空消息拒绝 |
| `git.review_commit_context` | `{ path }` | `{ diff, recent }` | 合并 diff（cached+worktree）+ `log -5 --oneline` |

## 5. 分期任务

- **Phase 0 · 后端 RPC 族**（rpc_git.rs，~1 天）：T0.1-T0.6 上表七 RPC +

- **Phase 2 · 刷新边界 + 消息区接入**（~1 天）：workspace tick 100ms debounce；
  turn 落定边沿（sessionListVersion）；focus/cwd 边沿；ChangedFilesCard 行点击
  升级 `openReviewForPath`（对齐 matchReviewFile 尾部匹配）；bridge.ts 注册。
- **Phase 3 · Ship-bar**（~1 天）：commit 输入 + commit/commitPush 分裂按钮
  （默认动作记忆）；busy 串行化 + 失败 toast；AI commit message 走
  `llm.oneshot`（instructions=commit_message 模板，input=commit_context）。

## 6. 验收

- agent 编辑文件 → 面板 ~100ms 内出现该文件；stage 后列表/±/diff 源即时翻转。
- 真仓库全流程：审查 → stage → commit（AI/手写 message）→ push；失败路径
  （非仓库、无 upstream、空消息）结构化提示。
- cargo check + tsc + vitest 全绿。

## 7. 工作量

Phase 0 → 1 → 2 线性，Phase 3 可并行；合计约 4-5 天。每期独立 commit
（`feat(review): phase-N ...`）。
