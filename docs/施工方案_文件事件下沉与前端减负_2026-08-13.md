## Phase 1: 文件事件权威源下沉（workspace.watch / workspace.changed）

### 现状缺口

- 文件树刷新源 = `tool.complete` 事件（Agent 工具改文件）+ 手动刷新按钮
- **外部变更**（编辑器/外部程序改文件）无感知 → 文件树陈旧
- 前端已有完整 workspace-events 系统（`src/lib/workspace-events.ts`，对齐 Hermes：pendingDirs/pendingFull + 500ms 去抖 + 消费端 consumeWorkspaceChange），**只差权威事件源**

### 目标链路

```
磁盘变更 → 后端 eleved（notify Recursive 监控，workspace.watch RPC 订阅）
         → WS 广播 workspace.changed { root, dirs, full }
         → 前端 workspace-events.ts notifyExternalChange()（复用现有 pendingDirs/pendingFull/去抖）
         → useFileTree consumeWorkspaceChange → 定向刷新（零改动）
```

**为什么放后端**：文件事件属于后端域（files.list/文件操作权威都在后端，单一真相源）；事件路径少一跳（壳做 = 磁盘→壳→前端→后端→前端）；与 tool.complete 双触发由前端 pendingDirs Set + 500ms 去抖**天然合并**，零额外机制。

### 1.1 后端：新模块 `crates/eleve-gateway/src/ws/workspace_watch.rs`

**依赖现状**：`notify = "6"` 已在 eleve-gateway Cargo.toml（零新增依赖）。

**结构**（对齐现有 PreviewFileWatchManager 模式 + WsConnRegistry 广播）：

```rust
pub struct WorkspaceWatchManager {
    /// watch_id → watcher（drop 即停止；单实例替换式，前端单文件树）
    watches: Mutex<HashMap<String, notify::RecommendedWatcher>>,
    /// notify 事件通道（std mpsc，消费线程聚合去抖，遵循 channel 铁律非回调）
    event_tx: mpsc::Sender<WatchEvent>,
    counter: AtomicU64,
}

enum WatchEvent {
    Changed { root: String, paths: Vec<PathBuf> },
    Renamed { root: String, from: PathBuf, to: PathBuf },
}
```

**消费线程逻辑**（tokio::spawn 或 std thread + 500ms 去抖窗口）：

1. 收集窗口内所有事件路径
2. 归一（对齐前端 dirOf 语义）：
   - 每个 path → 父目录绝对路径 → `dirs`（去重）
   - 路径不可锚定 / rename 跨目录 / 事件风暴（>32 路径）→ `full: true`
3. 排除规则（复用 `FILES_ALWAYS_EXCLUDED` + 硬排除 `.git`）：
   - watcher 侧：`Filter` 回调排除 `.git` / node_modules / target 等（notify 6 支持 `Watcher::watch` + filter）
   - 归一侧：dirs 里属于排除目录的丢弃
4. `build_event_frame("workspace.changed", json!({ root, dirs, full }))`
5. **广播**：遍历 `state.ws_conns`（WsConnRegistry，conn_id → tx）逐个 `tx.send(frame)`——对齐 broadcast_pool_changed 的全局广播模式（P3 根治 BUG-C 的教训：全局广播必须走连接表）

**RPC 端点**（ws/mod.rs 路由注册，对齐 files.* 风格）：

```rust
// workspace.watch — 订阅目录监控（幂等：同 path 替换；不同 path 替换旧 watcher）
"workspace.watch" => {
    let path = params.get("path").and_then(|v| v.as_str()).unwrap_or("");
    // 校验：path 存在且是目录
    // manager.replace_watch(id, path) → 返回 { watching: path, id }
}

// workspace.unwatch — 停止监控（前端卸载/切换 root 时调用）
"workspace.unwatch" => {
    // manager.remove_watch(id) → 返回 { stopped: true }
}
```

**AppState 挂载**：`state.workspace_watch: Arc<WorkspaceWatchManager>`（setup 时初始化 + spawn 消费线程）。

**生命周期**：单实例替换式（前端只有一棵活动文件树）。WS 断开后 watcher 残留 → 广播到空连接表（无害）；前端重连后重新 watch（见 1.6 注）。App 退出 = 进程结束，无泄漏。

### 1.2 前端：ws-client.ts 封装

对齐 voiceRecord 模式（GatewayWsClient 方法）：

```typescript
/** 订阅后端目录监控（文件外部变更 → workspace.changed 推送） */
async workspaceWatch(path: string): Promise<{ watching: string; id: string }> {
  return this.sendRpc('workspace.watch', { path })
}

/** 停止目录监控 */
async workspaceUnwatch(id: string): Promise<{ stopped: boolean }> {
  return this.sendRpc('workspace.unwatch', { id })
}
```

### 1.3 前端：workspace-events.ts 新增入口

```typescript
/** 后端 workspace.changed 事件入口（外部变更权威源；与 tool.complete 同源合并） */
export function notifyExternalChange(change: { root?: string; dirs?: string[]; full?: boolean }): void {
  if (change.full) {
    pendingFull = true;
  }
  for (const dir of change.dirs ?? []) {
    if (dir) pendingDirs.add(dir);
  }
  // 复用现有 fire()（500ms 去抖 + tick 递增），消费端零改动
  fire();
}
```

注：现 fire() 有 MIN_INTERVAL_MS 节流；外部事件同样受 500ms 窗口合并，与 tool.complete 同目录变更天然去重（Set）。

### 1.4 前端：useSSE.ts 事件 case

processEvent switch 加（对齐 voice.transcript 风格）：

```typescript
case 'workspace.changed': {
  // { root, dirs, full } → workspace-events 权威入口
  notifyExternalChange({
    root: (chunk.root as string) || undefined,
    dirs: Array.isArray(chunk.dirs) ? (chunk.dirs as string[]) : undefined,
    full: Boolean(chunk.full),
  });
  break;
}
```

### 1.5 前端：useFileTree.ts 订阅生命周期

```typescript
// rootPath 变化 → 重新订阅后端监控（WS 未连则静默失败 + 连接就绪后重试）
useEffect(() => {
  if (!rootPath) return;
  let cancelled = false;
  let watchId: string | null = null;

  const tryWatch = async () => {
    try {
      const res = await getWsClient().workspaceWatch(rootPath);
      if (!cancelled) watchId = res.id;
    } catch { /* WS 未连/失败 → 手动刷新兜底，连接恢复后重试 */ }
  };
  tryWatch();

  // 🔴 重连恢复：订阅 ws-client state==='connected' 变化，重发 watch
  const unsub = getWsClient().onStateChange((s) => {
    if (s === 'connected' && !watchId) tryWatch();
  });

  return () => {
    cancelled = true;
    unsub();
    if (watchId) {
      getWsClient().workspaceUnwatch(watchId).catch(() => {});
    }
  };
}, [rootPath]);
```

注意：onStateChange 是否已存在订阅接口（ws-client.ts 已有 `onStateChange`，见 waitForConnected 用法）✅；消费端 useWorkspaceTick 已由 FileBrowserPanel 接线，**零改动**。

### 1.6 Phase 1 验收标准

| 场景 | 预期 |
|------|------|
| 外部程序改文件（编辑器保存） | 文件树 ≤600ms 自动刷新，保留展开状态（定向 dirs） |
| 删除/新建目录 | 父目录定向刷新 |
| 大事件风暴（批量移动） | full 重扫兜底，不卡死 |
| Agent 工具改文件 | 与 tool.complete 合并，**不双刷**（500ms 窗口） |
| WS 断开重连 | 前端重发 watch，监控恢复 |
| .git/node_modules 内变更 | 不推送（排除规则） |
| 非活动 root 变更（多 root 场景） | 事件带 root，前端树按自身 root 消费 |

## Phase 2: 前端组织重构 + 渲染优化（减负主力）

**目标**：56,795 行 monolith → 按功能域拆分；每拆一个模块 = tsc 把关 + 该面板手动验证，**行为零回归**。

### 2.1 巨型组件拆分（优先级序）

| 文件 | 行数 | 拆分方案 |
|------|------|----------|
| `App.tsx` | 2018 | `useBootstrap`（启动编排：port/storage/profile/deps 门控）+ `usePanelLayout`（三栏状态/宽度/响应式）+ AppShell 布局壳 |
| `ProjectTreePanel.tsx` | 1918 | `useProjectTree`（projects.* RPC + 钻取状态机）+ ProjectRow/SessionRow 子组件 + 操作菜单 hook |
| `KanbanPanel.tsx` | 1374 | `useKanban`（列/卡状态 + CRUD RPC）+ KanbanColumn/KanbanCard 子组件 |
| `useGridChat.ts` | 1024 | 按职责拆：send 管线 / 事件吸收 / 审批交互（不拆状态——单一权威源在 hook 内） |

原则：**只拆组织，不动状态归属**（避免拆出平行状态源）；每个拆分 = 纯移动 + 引用修正，diff 无逻辑变更。

## 风险与回滚

| 风险 | 控制 |
|------|------|
| 事件风暴（大目录递归） | watcher 排除规则 + 500ms 聚合 + 归一限流（>32 → full） |
| 与 tool.complete 双刷 | pendingDirs Set 天然合并（同一目录只刷一次） |
| watcher 泄漏 | 单实例替换式 + unwatch 显式清理 + 进程退出兜底 |
| Phase 2 行为回归 | 每模块 tsc + 面板手动验证，纯移动无逻辑变更 |
| Phase 1 回滚 | 前端 unwatch RPC 即停；后端模块独立文件可整体删除 |
