## 三、BUG 清单（全部实证）

### 🔴 根因：累加器模型分叉

Hermes 流式 parts 按**事件到达序**交错（segment 模型），终稿重建与流式骨架同序。
ELEVE `StreamAccumulator` = `acc.text` 单字符串 + `acc.parts` 只装 tool，`finalizeAccumulator` 固定输出 `reasoning→tools→text`。
**流式按到达序、终稿按类型序，替换点必然跳变。** P1 #1/#3/#4/#8 均为其衍生。

## 四、修复方案（老大 2026-08-01 确认：重构 + Hermes 基线一并纳入）

### Phase 1 — 累加器 segment 化（根因重构）
对齐 Hermes `appendStreamPart` segment 模型：
- `StreamAccumulator` 重构：`acc.text` 单串 + `acc.parts` tool 列表 → **统一 segment 数组**（text/tool 按事件到达序交错，每个 segment 带稳定 id）
- reasoning 块化：`acc.reasoningBlocks[]`（reasoning.end 冻结当前块，下次 delta 新建），流式与终稿同构
- `processAccumulatorEvent`：message.delta 并入「当前 segment 内最近 text segment」（tool 为界）；tool.* upsert tool segment（先 flush 语义保留）
- `finalizeAccumulator`：按到达序输出；**serverContent 兜底仅限本轮从未收到 step.complete**（修 #8）
- 单视图 store parts 与累加器同构：`completeAssistantMessage` 整体替换 → **按 segment id diff 合并**（修 #1/#3/#4）
- 宫格 streamParts 同步迁移同一模型
- 解决：#1 #3 #4 #8 + P2-5

### Phase 2 — 系统消息归位（两视图统一）
- 单视图 status.update(goal/compressing/background) / interim.message / background.review / delegate.start/end → **独立 system 消息**（对齐宫格已有实现）
- 同一事件两视图同一产物
- 解决：#2 #13

### Phase 3 — 渲染层对齐 Hermes
- 3.1 isError 消费：MessageRow status 三值化（pending/done/error）+ 工具 error 图标红色样式 + groupStatus some(isError)（修 #6）
- 3.2 reasoning part 级 done 标记 + pending 自门控（仅「最后一个 reasoning 块 && 消息 pending」传 pending=true）+ **三态默认策略**（userOpen ?? pending：流式展开/完成折叠/用户覆盖永久）+ timerKey 块级唯一（修 #7）
- 3.3 稳定 key 全面替换 index key（segment id / toolCallId 拼接）（修 #4 残余）
- 3.4 流式/完成排版统一：流式也用 prose 兼容 line-height/margin，消灭高度突变（修 #5）
- 3.5 **工具永不分组重构**：ToolCallGroup 分组 → 每个工具独立成行 + 稳定 identity 容器（对齐 Hermes ToolGroupSlot，消灭落定重排）
- 解决：#5 #6 #7 + Hermes 基线纳入

### Phase 4 — 宫格止血 + P2 清理
- 4.1 宫格六连修：#9 error 空 parts 兜底上屏 errMsg / #10 累加器事件 session 守卫（对齐 message.complete）/ #11 ensureConnected 失败 toast / #12 interim 判 already_streamed / #14 abort 清 streamParts / P2-6 interrupted 标记
- 4.2 P2 清理：P2-1 sticky-bottom 键盘/拖拽解除 / P2-2 增量指纹 / P2-3 无图直渲 / P2-4 死代码三步法分析后删 / P2-7/8 already_streamed / P2-9 lifecycle 清消息 / P2-10 model.name 消费
- 解决：#9-#14 + P2×10

### 验证
每 Phase：Windows 侧 `tsc --noEmit` + `vite build`；全量完成后 `build_release.ps1` 打包。

### 铁律
- 共享处理器（processAccumulatorEvent/finalizeAccumulator）是累加器唯一权威，两视图不得手动处理已收录事件
- 流式/消息渲染走单一权威源 MessageRow
- 死代码三步法（grep 零消费 + git log 背景 + 风险点专项）后才可删
- 多人共用工作区禁 git add -A，必须 git add <具体文件>
