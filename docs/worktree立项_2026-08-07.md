# Worktree 独立立项：对齐 Hermes git worktree 全套（2026-08-07）

## 一、目标

Hermes「Start work」工作流全量移植到 ELEVE：从项目钻取视图的 repo 头部一键创建 git worktree（新分支 + 基线选择 + convert 已有分支），worktree lane 实时可见（含无会话的空 worktree），lane 可 reveal/复制路径/移除（dirty 升级 force）。

## 二、架构决策（防造轮子）

### 2.1 git 执行层放后端 eleved（WS RPC），不放 src-tauri

- **依据**：ELEVE 文件操作（files.list/rename/delete）与 git 探测（`git_probe.rs`：run_git_multi/-C cwd/CREATE_NO_WINDOW/超时）全部在后端；业务权威在后端、前端薄壳是 ELEVE 既定架构（对齐 Hermes 的 Electron-main-git 在 ELEVE 的对应物 = eleved 进程）。
- **不造轮子**：复用 `git_probe.rs` 的 `GitProbe`（worktree 根探测缓存）不动；新增 `ws/rpc_git.rs` 的 `run_git` 是**交互式 git 操作**（30s 超时 + stderr 错误传播，探测用 1.5s 吞错语义不符，不强行复用 run_git_multi）。
- **不做**：src-tauri 加 git（要重编 tauri 壳 + 破坏"业务在后端"分层）。

### 2.2 数据结构对齐 Hermes（global.d.ts）

- `HermesGitWorktree { path, branch: string|null, isMain, detached, locked }` — `git worktree list --porcelain` 解析（首条 isMain）
- `HermesGitBranch { name, checkedOut, isDefault, worktreePath }` — for-each-ref refs/heads + worktree 映射
- `HermesGitBaseBranch { name, isRemote, isDefault }` — refs/heads + refs/remotes，origin/HEAD 或本地 trunk 标记默认

### 2.3 命令语义（git-worktree-ops.ts 逐条移植）

| 操作 | 命令 | 备注 |
|------|------|------|
| list | `worktree list --porcelain` | 解析 worktree/branch/detached/bare/locked，首条 isMain |
| add 新建 | `worktree add -b <branch> <dir> [base]` | base=origin/ → 先 fetch 该分支 + `--no-track`；branch 已存在 → 重试 `worktree add <dir> <branch>` |
| add convert | 默认分支 → `switch <branch>`（主 checkout）；否则 `worktree add <dir> <branch>` | |
| remove | `worktree remove [--force] <dir>` | 从 mainRoot 执行；dirty/locked 报错 → 前端升级 force |
| branch list | `for-each-ref --format=%(refname:short) --sort=-committerdate refs/heads` | +worktree 映射 checkedOut/worktreePath + trunk 判定 |
| base branch | `for-each-ref refs/heads refs/remotes` | isRemote=origin/ 前缀；isDefault=origin/HEAD 或本地 trunk |
| switch | `switch <branch>` | |
| 前置 | 非 repo → `init` + `commit --allow-empty`（-c user.email/name 内联） | 新项目文件夹 worktree "just work" |
| 目录 | `<mainRoot>/.worktrees/<slug>`（唯一化 -2/-3） | mainRoot = worktree list 首条 |
| 消毒 | sanitizeBranch（空格→-，去非法字符）+ slugify（小写 slug 40 字符） | 前端实时 + 后端双保险 |

### 2.4 视觉 lane 注入（mergeRepoWorktreeGroups 移植到前端）

项目钻取视图：`git.worktree_list` 结果与后端 lane（projects.project_sessions 的 isMain/isKanban/label/path）合并——
1. 主 checkout 折叠为 home lane（live branch 标签，默认 main）
2. linked worktree lane relabel 成 live branch / 路径修复（git truth 优先）
3. 注入空视觉 lane（有 worktree 无会话也显示）；kanban task worktree（`<repo>/.worktrees/t_*`）排除；按 id/path/label 去重
