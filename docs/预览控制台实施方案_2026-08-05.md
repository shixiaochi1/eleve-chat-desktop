## 一、背景与目标

Hermes 预览面板底部有一个**页面控制台**：实时显示被预览页面（dev server）的
console.log/warn/error/info 消息（含 source:line），支持行级复制/发送给 Agent、
清空、高度拖拽、自动滚底。这是 Agent 开发调试闭环的关键一环——页面报错
（尤其 module mime 类）不再靠猜，Agent/用户直接看到页面 console。

**ELEVE 现状**：预览用 `<iframe>` 加载，**跨域 iframe 拿不到页面 console**
（浏览器安全模型）。此前标注"P2-1 技术限制不做"；老大点名要做。

## 二、技术路径（已逐层实证）

**核心思路**：iframe → **Tauri 内嵌子 Webview**（Hermes Electron webview tag 的
Tauri 等价物），Rust 侧注入初始化脚本捕获 console，经 Tauri IPC 回传主窗口。

```
主窗口内创建第二个 webview（label=preview，加载 http://localhost:3000）
  → WebViewBuilder.initialization_script 注入：
     重写 console.log/warn/error/info/debug →
     调 window.__TAURI_INTERNALS__.invoke('preview_console_push', {level,text,source,line})
  → Rust 命令 handler → app.emit("preview-console", payload)
  → 主窗口前端 listen → ConsolePanel 渲染
```

### 可行性证据（源码实证）

| 能力 | 证据 |
|------|------|
| 远程 URL 子 webview | 前端 `@tauri-apps/api/webview` `Webview` class（webview.d.ts L106）+ Rust `WebviewBuilder::new(label, WebviewUrl::External(url))` |
| 初始化脚本注入 | Rust `WebviewBuilder::initialization_script()`（tauri-2.11.2 webview/mod.rs L868）；WebView2 AddScriptToExecuteOnDocumentCreated 在远程页面 document 创建时执行（页面 CSP 之前） |
| IPC 桥覆盖远程页面 | Tauri 对所有 webview 注入 `__TAURI_INTERNALS__`（含远程）；`handle_ipc_message`（ipc/protocol.rs L155）**无 origin 拒绝**，权限由 capability 控制 |
| 权限精确授权 | capability 支持 `windows: ["main"]` + `webviews: ["preview"]` 组合；只放行 console 推送命令（最小权限） |
| 位置/大小同步 | `core:webview:allow-set-webview-position/size` 权限已在 default.json；前端 `Webview.setPosition/setSize` |
| 事件回传 | Rust `app.emit` + 前端 `listen`（既有事件通道，零新机制） |

### 平台覆盖
- Windows：WebView2 `AddScriptToExecuteOnDocumentCreated` ✓
- macOS：WKUserScript atDocumentStart ✓
- Linux：webkitgtk 同构 ✓

## 三、与 Hermes 的差异（对齐边界）

| Hermes（Electron webview） | ELEVE（Tauri 子 webview） | 处理 |
|---|---|---|
| console-message 事件原生 | 注入脚本重写 console.* | 语义等价；注入脚本能拿到 args 序列化 + Error.stack 提取 source:line |
| webview tag 在 DOM 布局 | 原生层 webview，不占 DOM | ResizeObserver → setPosition/setSize 联动（右栏拖拽调宽时实时同步） |
| 安全：webview 直接加载 | 同款（无 iframe sandbox） | URL 协议白名单（http/https）保留；风险等价 Hermes，可接受 |
| send-to-agent 按钮 | 需 InputArea 注入机制 | 先做行复制 + 发送按钮（若 InputArea 有现成注入 API 则接，否则留复制） |

## 五、决策结论（2026-08-05 讨论定稿）

**老大原则：① 有现成成熟实现直接拿，不发明轮子；② 功能全量对齐 Hermes，不简化不遗失；
③ 复杂运算/状态缓冲下沉 Rust 侧，性能与内存管理先行。**

| 决策点 | 结论 | 依据 |
|---|---|---|
| 布局同步 | **方案 A：实时同步**（ResizeObserver → setPosition/setSize，复用 PaneShell rAF 模式） | 功能完整，体验与 iframe 一致 |
| 分批 | 步骤 A（webview 渲染+数据链路）→ 步骤 B（ConsolePanel UI），A 后先验收 | 工程可控 |
| send-to-agent | **必做，全量对齐**：新建 `lib/composer-events.ts`（**直接移植 Hermes focus.ts 的 window CustomEvent 总线模式**：dispatch/subscribe/INSERT_EVENT），InputArea 订阅 → 复用自身 insertTextAtCursor（零重复逻辑）；ConsolePanel 发送按钮 → requestComposerInsert | 现成成熟实现直接拿；Hermes 同款机制 |
| devtools 入口 | **必做**：Hermes preview-pane 有 devtools 开关（devtoolsOpen 状态 + 按钮），全量对齐 | 功能不遗失 |
| console 面板 UI | **全量移植 Hermes preview-console.tsx**（分级着色/source:line/复制/发送/清空/拖拽/滚底），不做简化版 | 现成成熟实现直接拿 |
| console 数据链路 | **Rust 侧缓冲治理 + 批量推送**（见下方架构），前端只消费增量事件 | 原则③：性能/内存管理下沉 |

### 🔴 原则③落地：console 数据链路架构（Rust 侧治理）

页面疯狂 log（每秒数百条）时，直接逐条 IPC→事件→React 渲染 = 前端卡死。
**Hermes 是直接灌 renderer（无治理层）；ELEVE 链路经过 Rust，正好做治理——比 Hermes 更优。**

```
预览 webview 页面
  → 注入脚本捕获 console.* → 序列化截断（单参 1KB）→ invoke('preview_console_push')
  → Rust PreviewConsoleBuffer（state 注入，Mutex<VecDeque<ConsoleEntry>>）
      ├─ 环形上限：2000 条（超限丢最旧）
      ├─ 单条上限：4KB（超限截断 + 标记 truncated）
      ├─ 重复合并：连续同 level+text → 计数（防刷屏风暴）
      └─ 批量推送：100ms flush 定时器 → emit('preview-console', { seq 游标, batch })
  → 前端 store 按 seq 增量追加（断档则全量拉取命令 preview_console_snapshot）
```

- **前端零高频调用**：只收 100ms 批量的增量事件 + 手动 snapshot 命令
- **内存有界**：缓冲容量上限由 Rust 持有，tab 关闭 → 销毁 webview + drop 缓冲；
  页面导航（navigate）→ 清缓冲（新页面新会话）
- **webview 生命周期统一 Rust 管理器** `PreviewWebviewManager`（state 注入）：
  create/close/update/navigate 一个命令入口，前端只传意图，原生层操作全在 Rust
- **布局同步**：前端 rAF 节流（每帧至多一次）→ update 命令（position+size 合并传），
  计算量小（两个坐标）但频率高，IPC 开销可控

## 六、施工清单（定稿）

### Rust 侧（src-tauri，核心治理层）

### 前端（薄层，只消费）
5. `lib/composer-events.ts`：移植 Hermes focus.ts 事件总线（requestComposerInsert + InputArea 订阅）
6. PreviewWebPane 渲染层：iframe → 子 Webview（创建/销毁/布局同步/浏览器模式 fallback）
7. ConsolePanel：全量移植 Hermes preview-console（分级/source:line/复制/发送/清空/拖拽/滚底）
8. console store：per tab，按 seq 增量追加 + snapshot 补拉
9. devtools 开关按钮（对齐 Hermes preview-pane devtoolsOpen）

## 七、风险与回退

- **远程页面 invoke 被未来 Tauri 版本收紧**：若 handle_ipc_message 加 origin 校验，
  console 链路断——回退方案：注入脚本改走 `window.postMessage` + 本地代理页中转
  （preview-host.html 内嵌 iframe 同源策略受限，需 Rust http 代理，复杂度高）
- **WebView2 注入脚本被页面移除**：极端页面可删除全局注入——Hermes 同款风险，忽略
- **多 webview 布局竞态**：创建时机在 tab 激活后（先占位后创建），销毁在 tab 关闭

### 实现清单
- Rust：`preview_console.rs`（环形 2000×4KB/重复合并/100ms flush/per-label seq/注册表）+ `preview_webview.rs`（create/close/update/navigate/reload/visible/devtools + on_page_load 事件）+ `inject/preview-console-capture.js` + capabilities/preview.json + lib.rs 接线 + build.rs AppManifest
- 前端：`lib/composer-events.ts`（Hermes focus.ts 最小集）+ `store/preview-console.ts` + `PreviewConsolePanel.tsx`（全量移植）+ PreviewWebPane iframe→子 Webview + devtools 按钮
- 单元测试：12 个（环形/截断/合并/seq/注册/clear/remove/drain），Windows 侧 cargo test 全过

### 踩坑记录（均为源码实证级根因）
1. **同步命令 + add_child 自死锁**：Tauri IPC 回调跑 UI 线程，add_child 内部 run_on_main_thread 阻塞等待主线程 → 死锁（页面空白、无任何日志）。修复：命令改 `async fn`（tokio 线程执行）。DeepSeek 老命令是 async 故从未踩坑
2. **远程页面 IPC 三层权限缺一不可**：capability ① webviews glob（`preview-*`）② remote urls 声明（URLPattern）③ **自定义命令必须 build.rs `AppManifest.commands` 注册 + capability permissions 显式 `allow-*`**——缺 ③ 时远程 invoke 被静默拒绝（注入脚本 try/catch 吞掉，无任何日志）。has_app_acl=true 后 Local 命令同样严格 ACL → default.json 必须补齐全部 allow-*（14 个）
3. **子 webview 是原生 HWND，DOM 覆盖层/面板被盖住**（z-index 无效）：控制台面板必须嵌入 flex 布局（webview 高度联动收缩），错误覆盖层配合 hide/show 命令
4. **wry Windows `is_devtools_open()` 硬编码 false、`close_devtools()` 空函数**：devtools 不能 Rust 侧 toggle，改前端状态驱动 + 显式 open 参数；关闭 devtools 窗口需手动（Alt+F4）——平台限制
5. **`--ui-accent-primary` 从未定义**：按钮背景透明 + 白字 = 融为一体。改用 ELEVE 标准 `bg-primary text-primary-foreground`
6. **PreviewConsolePanel absolute 定位**（Hermes 覆盖式布局移植）在 flex 嵌入布局下定位到页面底部不可见 → 改普通流元素

### 遗留
- devtools 窗口无法程序化关闭（wry 平台限制）
- 重启 preview server 依赖父 session（后端契约 session not found 报错）；无会话时前端按钮 disabled（可后续加提示）
